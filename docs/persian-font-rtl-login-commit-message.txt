Fix remaining Persian font surfaces and RTL label placement

Use PersianTextView for animated proxy subtitles, account information actions,
login labels, country-switcher entries, phone confirmation and bot command rows.
Keep the optional script-specific behavior and preserve ASCII phone numbers,
emoji, code spans and the original Regular/Medium/Bold weight hierarchy.

Style owner/admin labels before measuring them and round their reserved width
up. Normalize the badge text origin by subtracting StaticLayout.getLineLeft(0)
without moving the badge background or its hit target.

Fix bot-menu labels appearing far to the right of their button in Persian.
The baseline implementation lays out the label in a wide ALIGN_NORMAL layout
but positions it using the visible line width. RTL text therefore has an
internal left offset which was never removed when drawing. Subtract that
offset, clip the label to the animated expansion area, and invalidate the
cached layout when the font setting changes. The positioning corrections
also apply with Vazirmatn disabled. Both missing line-offset corrections are
present in this repository's HEAD, independently of the added font support;
this observation is based on source inspection, not a stock Telegram APK test.

Apply a central 0.94 optical size factor inside PersianFontSpan for both
measurement and drawing. This makes the styled script slightly smaller and
visually lighter without changing base TextPaint sizes or reducing semantic
font weights. The factor is an initial visual adjustment requiring device
review, not a calibrated match to every Android fallback font.

Add regressions for optical sizing, proxy subtitle refresh and visible bot-menu
label bounds in RTL/LTR with the font enabled and disabled. The suite now has
24 tests. Java syntax/import/whitespace checks were performed; no app build,
device run or instrumentation execution was requested for this pass.
