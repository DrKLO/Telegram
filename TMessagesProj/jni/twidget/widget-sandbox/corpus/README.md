# corpus — the HTML files every demo and test suite loads

Single source of truth; `packages/core/scripts/build-native-bundles.ts` copies `compat`,
`attacks` and `generated/*` into the iOS/macOS, Android and desktop demo apps.
Run one file in the sandbox without a demo:
`corepack pnpm tsx packages/core/scripts/sandbox-node.ts corpus/compat/tabs.html --verbose`.

| Folder | What | Used by |
|---|---|---|
| `compat/` | 19 hand-written widgets (calculator, tabs, SVG and canvas charts drawn by hand, drag, animations, per-message storage restored on load, WebGL fallback…); 7 are the in-profile reworks of `out-of-profile/` files: `svg-bar-chart`, `svg-line-chart`, `canvas-bar-chart`, `canvas-line-chart`, `notes-storage`, `quiz-buttons`, `table-sort` | `test:compat`, demos |
| `out-of-profile/` | 9 former `compat/` widgets that need what widget profile 1 leaves out: bundled Chart.js and D3 (`chartjs-*`, `d3-*`) and form controls (`form-validation`, `inputs`, `local-storage`, `quiz`, `sortable-table`); kept unchanged to show what the profile removes (`?file=out-of-profile/<name>` in the dev app), run by no suite (`docs/profile-v1.md`). Seven are reworked in profile in `compat/`: `d3-bar` → `svg-bar-chart`, `d3-line` → `svg-line-chart`, `chartjs-bar` → `canvas-bar-chart`, `chartjs-line` → `canvas-line-chart` (drawn by hand), `local-storage` → `notes-storage`, `quiz` → `quiz-buttons`, `sortable-table` → `table-sort` (buttons and taps instead of inputs); `form-validation` and `inputs` are about form controls and have no rework | dev app |
| `attacks/` | 104 files that each try to reach the network or run code (`markup-*`, `css-*`, `api-*`, `nav-*`, `cpu-*`, `fallback-*`, `timer-flood`, `mem-*`, `activation-*`), or to get round the rules of requests to the bot (`request-*`: no request without a tap, a forged wire, a background flood, two in flight, a copy) | `test:attacks`, demos; must be 0 canary hits |
| `generated/with-profile/`, `generated/without-profile/` | 20 LLM-generated widgets each, same prompts, with/without `docs/widget-runtime-profile.md` in context; `manifest.json` has the prompts | `test:generated`, demos |
| `htmlbubbles-ported/` | 116 chat-demo messages (12 conversations) written as classic widgets (plain HTML+CSS+JS, no `render()`/`onAction`); conventions and status in its README | `test:htmlbubbles`, web picker, demos (`--autorun htmlbubbles`) |
| `showcase/3d`, `showcase/travel`, `showcase/commerce`, `showcase/life`, `showcase/work` | 27 interactive, animated demos on the **full web profile** (transitions, keyframes, grid, projected 3D on canvas 2D, SVG, canvas, pointer drag/swipe, live clocks), one realistic chat case each: boarding pass, ride tracking, smart home, kanban, live poll …; conventions and status in `showcase/README.md` | `test:showcase`, web picker, the web chat feed (`?feed=1`, its default corpus) |
| `common/cards`, `common/interactive`, `common/live`, `common/heavy` | 32 widgets on the **common profile** — only what WebView, Blitz and litehtml all render the same way (flex, tables, gradients, `var()`, generic font families; no grid/SVG/canvas/transforms/shadows/forms/emoji), so renderer timings compare like for like; choices kept in `localStorage`, links through `TelegramWidget.openLink`; profile and status in `common/README.md` | `test:common`, web picker, demos (`--autorun common`), Android bench (`CORPUS=common`) |
| `defaults/static`, `defaults/interactive` | 6 widgets with little or no CSS that look native through the renderer's UA layer (v0.1.1): text card, list, table, link card, FAQ with `<button>`, survey; conventions in `defaults/README.md` | `test:defaults`, web picker, demos, the test group's Defaults topic |
| `gestures/1-pairs`, `2-horizontal`, `3-vertical` | what the horizontal-only rule (v0.1.3: vertical drags are always the chat's) removed: a joystick game and 2048, each on `touch-action: none` (`-xy`) and on `pan-y` (`-x`), now alike, and a wheel picker (`pan-x`) that no longer turns; what is fine with horizontal only (`pan-y`): a paddle game, a card carousel, a range slider; `gestures/README.md` | `test:gesture-corpus`, web picker, the web feed (`corpus=gestures`), the test group's Gestures topic (`--topic gestures`) |
| `interactive/` | 4 widgets on the widget's state and requests: a poll, tic-tac-toe against the bot, a live ticker on background requests, a promo code with `copyText`; each names the dev app's mock bot that answers it (`<meta name="tw-bot">`); `interactive/README.md` | web picker with the **Bot (mock)** panel, `tests/sdk.spec.ts` (the poll) |
| `resize/1-default`, `2-grows-up`, `3-grows-down` | one widget per resize anchor (`TelegramWidget.setResizeAnchor`, v0.1.3): an FAQ on the default (top), a support thread that grows upward (bottom), search results that grow downward (top, said explicitly); `resize/README.md` | `test:resize-corpus`, web picker, the test group's Resize topic (`--topic resize`) |
