Terms of Messaging
Nested numbering is generated by CSS counters(clause, ".") — no numbers in the HTML
  1. Definitions. In these terms, “Message” means any HTML document sent through the service, and “Bubble” means its rendered representation.
    1. A Message may contain markup, inline styles and style blocks.
    2. A Message may not contain executable code; any such code is ignored.
      1. This includes <script> elements and event-handler attributes.
      2. It also includes javascript: links, which are treated as ordinary text.
    3. “Interactive state” means the set of keys toggled by chat: links.
  2. Rendering. Each Message is laid out independently.
    1. Styles declared in one Message shall not affect any other Message.
    2. Bubbles shrink to the natural width of their content, up to a maximum width.
    3. Content wider than the maximum width is clipped at the Bubble edge.
  3. Images. Only images available synchronously are displayed.
    1. Permitted sources are data:, sf:, app: and local files.
    2. Remote images are not fetched in this version.
  4. Miscellaneous. If any clause is found unenforceable, the remaining clauses continue to render.
    1. Headings in these terms are for convenience only.
    2. These terms are themselves a Message and are bound by them.
